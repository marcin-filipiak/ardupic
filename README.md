# Arduino core ``ardupic`` (SDCC + gputils)

An Arduino platform (direct "hardware/") for **Microchip PIC** microcontrollers:

| Board | Core | Architecture | Flash | RAM | ADC |
|---|---|---|---|---|---|
| **PIC18F25K80** (28-pin) | `pic18f25k80` | pic16 (SDCC `-mpic16`) | 32 kB | 2 kB | 12-bit, A0..A7 |
| **PIC18F2550** (28-pin) | `pic18f2550` | pic16 | 32 kB | 2 kB | 10-bit, A0..A10 |
| **PIC18F4550** (40-pin) | `pic18f4550` | pic16 | 32 kB | 2 kB | 10-bit, A0..A13 |
| **PIC16F877A** (40-pin) | `pic16f877a` | pic14 (SDCC `-mpic14`) | 8 kB | 368 B | 10-bit, A0..A7 |

The compiler is **SDCC** (C), the assembler/linker is **gputils**, and thanks to
`arduino-cc` (a wrapper around the `platform.txt` recipes) the whole thing works
directly with **Arduino CLI** and **Arduino IDE 2.x**.

> Note: SDCC does not support C++ — both sketches and the core must be written in C.
> `.ino` files do compile (they are processed as C by `arduino-cc`), but there are no
> objects, `String`, etc.

## Quick start

### 0. Install via Arduino Board Manager (recommended)

In the Arduino IDE: **File → Preferences → Additional boards manager URLs**, paste:

```
https://raw.githubusercontent.com/marcin-filipiak/ardupic/main/package_ardupic_index.json
```

then **Tools → Board → Boards Manager** → search for **ardupic** → Install.

With Arduino CLI:

```bash
arduino-cli config add board_manager.additional_urls https://raw.githubusercontent.com/marcin-filipiak/ardupic/main/package_ardupic_index.json
arduino-cli core update-index
arduino-cli core install marcinfilipiak:ardupic
```

The install downloads and unpacks the platform together with the **full bundled
toolchain** (SDCC + gputils for Linux x86_64) — nothing else needs to be installed
by hand. FQBN: `marcinfilipiak:ardupic:<board>`.

> Note: `package_ardupic_index.json` is generated by `release.sh` (it packages the
> platform and computes the SHA-256). After changing the core run `./release.sh`,
> bump the version in `platform.txt` and push to the repository.

### 1. Local install (without Board Manager)

```bash
./install.sh            # installs to ~/Arduino/hardware/marcinfilipiak/ardupic by default
./install.sh /path/to/arduino/user/dir   # or a custom directory
```

### 2. Build test

```bash
arduino-cli compile -b marcinfilipiak:ardupic:pic18f25k80  examples/Blink
arduino-cli compile -b marcinfilipiak:ardupic:pic18f2550   examples/Blink
arduino-cli compile -b marcinfilipiak:ardupic:pic18f4550   examples/SerialAin
arduino-cli compile -b marcinfilipiak:ardupic:pic16f877a   examples/SerialAin
```

Resulting image: `build/<sketch>.ino.hex` (Intel HEX, loaded at address 0).

### 3. Upload (PICprog)

```bash
arduino-cli upload -b marcinfilipiak:ardupic:pic18f2550 -p /dev/ttyUSB0 examples/Blink
```

The platform ships with **PICprog 1.9.1** (see `toolchain/picprog/`); the bundled
driver `tools/picprog-upload` translates the Arduino arguments into a PICprog call.
The default programmer is **JDM** (simple serial/FTDI); set `PICPROG_HW=k8048` to use
a K8048 instead. PIC18F2550/4550 and PIC16F877A are supported natively by PICprog;
PIC18F25K80 uses an added device-table entry that is still **untested on hardware**.

| `UsbSerial` | 2550/4550 | USB CDC echo |
| `UsbSerialSend` | 2550/4550 | USB CDC transmit (periodic data) |
| `UsbSerialReceive` | 2550/4550 | USB CDC receive (command interpreter) |
| `CanSend` | 25K80 | CAN transmit (standard + extended frames) |
| `CanReceive` | 25K80 | CAN receive (ISR-fed queue) |

```bash
arduino-cli compile -b marcinfilipiak:ardupic:pic18f25k80 examples/CanSend
arduino-cli compile -b marcinfilipiak:ardupic:pic18f2550 examples/UsbSerialSend
```

USB CDC needs the on-chip USB (RC4/RC5); CAN needs an external transceiver
(MCP2551, SN65HVD230, …) and bus termination.

## Pin mapping

Numbering: **pin = port×8 + bit** (port 0 = PORTA, 1 = PORTB, 2 = PORTC, ...).
E.g. RC6 → 2×8+6 = 22.

### PIC18F25K80 (28-pin)

| Arduino | MCU | Function | Arduino | MCU | Function |
|---|---|---|---|---|---|
| 0 | RA0 | AN0/A0 | 13 | RB5 | **LED_BUILTIN** |
| 1 | RA1 | AN1/A1 | 14 | RB6 | digital |
| 2 | RA2 | AN2/A2 | 15 | RB7 | digital |
| 3 | RA3 | AN3/A3 | 16 | RC0 | digital |
| 4 | RA4 | digital | 17 | RC1 | digital |
| 5 | RA5 | AN4/A4 | 18 | RC2 | **PWM (CCP1/P1A)** |
| 6 | RA6 | digital | 19 | RC3 | digital |
| 7 | RA7 | digital | 20 | RC4 | digital |
| 8 | RB0 | INT0/AN10/A5 | 21 | RC7 | **RX** |
| 9 | RB1 | INT1/AN8/A6 | 22 | RC6 | **TX** |
| 10 | RB2 | INT2 | 25 | RD6 | digital |
| 11 | RB3 | AN9/A7 | 26 | RD7 | digital |
| 12 | RB4 | digital | | | |

### PIC18F2550 (28-pin)

| Arduino | MCU | Function | Arduino | MCU | Function |
|---|---|---|---|---|---|
| 0 | RA0 | AN0/A0 | 9 | RB1 | INT1/AN10/A6 |
| 1 | RA1 | AN1/A1 | 10 | RB2 | INT2/AN8/A7 |
| 2 | RA2 | AN2/A2 | 11 | RB3 | AN9/A8 |
| 3 | RA3 | AN3/A3 | 12 | RB4 | AN11/A9 |
| 5 | RA5 | AN4/A4 | 13 | RB5 | AN13/A10 |
| 8 | RB0 | INT0/AN12/A5 | 18 | RC2 | **PWM (CCP1/P1A)** |

TX = 22 (RC6), RX = 23 (RC7). External **20 MHz** crystal, HS-PLL → 48 MHz.

### PIC18F4550 (40-pin)

Pins 0..6 = RA0..RA6, 8..15 = RB0..RB7, 16..23 = RC0..RC7,
24..31 = RD0..RD7, 32..34 = RE0..RE2. RA7 does not exist (guarded in the API).

Analog: A0..A4 = RA0..RA3/RA5, A5..A7 = RE0..RE2 (AN5..AN7),
A8=RB2/AN8, A9=RB3/AN9, A10=RB1/AN10, A11=RB4/AN11, A12=RB0/AN12,
A13=RB5/AN13. TX = 22, RX = 23. External **20 MHz** crystal, HS-PLL → 48 MHz.

### PIC16F877A (40-pin)

Pins 0..5 = RA0..RA5, 8..15 = RB0..RB7, 16..23 = RC0..RC7,
24..31 = RD0..RD7, 32..34 = RE0..RE2. RA6/RA7 are the crystal pins (OSC1/OSC2) —
unusable. Analog A0..A3 = RA0..RA3, A4 = RA5 (AN4), A5..A7 = RE0..RE2
(AN5..AN7). TX = 22 (RC6), RX = 23 (RC7). **XT 4 MHz** jumper oscillator.

## Peripheral support

- **ADC** — `analogRead(A0..A?)`: **12-bit (0..4095)** on the K80, **10-bit (0..1023)**
  on the 2550/4550/877A. Vref+ = VDD, Vref− = VSS. During a read only the selected
  ADC channel is enabled (PCFG/ADCON1 control), after which the pins return to digital.
- **PWM** — pin 18 only (CCP1/ECCP1/P1A), `analogWrite(pin, 0..255)`;
  frequency `Fosc/(4·256)`.
- **UART1** — TX = pin 22 (RC6), RX = pin 23 (RC7). Global functions `uart1_*`
  (see below). Baud rates: 4800, 9600, 19200, 38400, 57600.
- **CAN** — PIC18F25K80 only (ECAN, legacy mode). CANTX = pin 22, CANRX = pin 23 —
  the same pins as UART1, so CAN and UART1 are **mutually exclusive**.
- **USB CDC** — PIC18F2550/4550 only (virtual serial port), functions `usbcdc_*`.
- **Time** — `millis()` every 1 ms (Timer0 16-bit on PIC18, Timer1 on PIC16F877A);
  `micros()` with ~0.5 µs (PIC18) / 1 µs (877A) resolution.
- **Shift** — `shiftIn` / `shiftOut` (bit-bang).

## API

Standard (Wiring-style, but in C): `pinMode`, `digitalWrite`, `digitalRead`,
`analogRead`, `analogWrite`, `millis`, `micros`, `delay`, `delayMicroseconds`,
`shiftIn`, `shiftOut`, `attachInterrupt`, `detachInterrupt`, the macros
`min/max/abs/constrain/radians/degrees/round/sq` and bit macros (`bitRead`,
`bitSet`, `bitClear`, `lowByte`, `highByte`, `bit`), plus the constants
`HIGH/LOW`, `INPUT/OUTPUT/INPUT_PULLUP`, `RISING/FALLING/CHANGE`.

External interrupts:

| Board | Pins |
|---|---|
| PIC18F25K80 / 2550 / 4550 | 8 (INT0), 9 (INT1), 10 (INT2) |
| PIC16F877A | 8 (INT0 only) |

Serial (no objects — global `uart1_*` functions):

| Function | Arduino equivalent |
|---|---|
| `uart1_begin(baud)` | `Serial.begin()` |
| `uart1_write(c)` | `Serial.write()` |
| `uart1_print(s)` | `Serial.print(s)` |
| `uart1_println(s)` | `Serial.println(s)` |
| `uart1_print_int(v)` / `uart1_print_ulong(v)` | `Serial.print(number)` |
| `uart1_read()` / `uart1_available()` | `Serial.read()` / `Serial.available()` |

USB CDC (PIC18F2550/4550, no objects — global `usbcdc_*` functions):

| Function | Arduino equivalent |
|---|---|
| `usbcdc_begin()` | attach the USB module and wait for enumeration |
| `usbcdc_poll()` | service USB events (call from `loop()`) |
| `usbcdc_write(c)` | `Serial.write()` |
| `usbcdc_print(s)` / `usbcdc_println(s)` | `Serial.print(s)` / `Serial.println(s)` |
| `usbcdc_print_int(v)` / `usbcdc_print_ulong(v)` | `Serial.print(number)` |
| `usbcdc_read()` / `usbcdc_available()` | `Serial.read()` / `Serial.available()` |

The blocking I/O functions service the USB engine themselves, so `usbcdc_poll()` is
optional — using it in `loop()` improves responsiveness.

CAN (PIC18F25K80 only):

| Function | Description |
|---|---|
| `can_begin(baud)` | enable CAN at the given baud (125/250/500/1000 kbit); 1 = ok |
| `can_send_std(id, data, len)` | send a standard frame (11-bit ID); 1 = ok |
| `can_send_ext(id, data, len)` | send an extended frame (29-bit ID); 1 = ok |
| `can_send(msg)` | send a `can_message_t`; 1 = ok |
| `can_available()` | number of frames waiting in the RX queue |
| `can_read(msg)` | dequeue the oldest frame; 1 = read, 0 = queue empty |

Reception is handled in an interrupt (RXB0/RXB1 → queue); transmission is blocking.

## Chip configuration (CONFIG bits)

Location: `cores/<board>/Arduino.c`:

- **PIC18F25K80**: `FOSC=INTIO2` → internal 16 MHz, `WDTEN=OFF`, `XINST=OFF`,
  `CANMX=PORTC` (CAN on RC6/RC7).
- **PIC18F2550 / 4550**: `FOSC=HSPLL_HS`, `PLLDIV=5`, `CPUDIV=OSC1_PLL2`,
  `USBDIV=2`, `VREGEN=ON` → external 20 MHz crystal, **48 MHz** CPU and USB
  (full speed); `PWRT=ON`, `BOR=OFF`, `WDT=OFF`, `LVP=OFF`, `XINST=OFF`,
  `PBADEN=OFF` — via `#pragma config` (gpasm knows the names from `gpcfg-table.c`).
- **PIC16F877A**: `__code unsigned int __at(0x2007) __CONFIG = 0x3FF1`
  (XT, WDT off, LVP off) — SDCC pic14 does not support `#pragma config`.

Changing the clock requires editing `F_CPU` in `boards.txt` and the timer preload
in `isr.c`.

## How it works (toolchain)

`arduino-cc <mode> <DEVICE> ...` translates the `platform.txt` recipes into tool
invocations (DEVICE e.g. `PIC18F2550` / `PIC16F877A` — the SDCC/gpasm/gplink
processor names are derived from it):

```
C/C (.ino, .cpp, .c)
   │ sdcc -S -m<pic16|pic14> -p<device> --std-c99
   ▼
   .asm
   │ gpasm -c -p<device> (-I header/)
   ▼
   .o  ──►  core.a  (gplib)
   │
   ▼  gplink  <lkr> + crt0 (pic16) + libdev + libsdcc + libc...
   .hex
```

On the PIC16F877A (pic14) the libraries are: `libsdcc.lib` (startup + `__interrupt`),
`libc.lib`, `pic16f877a.lib` (SDCC non-free device lib). The SFR header
`pic16f877a.h` is included (SDCC non-free → `--no-warn-non-free`).

Key techniques:

- **SFRs as symbols (pic16):** SDCC emits references like `_LATB`; gputils 1.4 does
  not allow a global `EQU` in relocatable code (Error[156]). Solution: one
  **absolute UDATA section** per register address, covered by a `PROTECTED DATABANK`
  in the `.lkr`; regeneration: `gen_sfr_lib.sh <device>`.
- **One ISR per priority (pic16):** a single `void _isr(void) __interrupt(1)`
  (vector 0x08) dispatches Timer0 / INT0 / INT1 / INT2 (and CAN on the K80). Pic14:
  a single `__interrupt(0)` (vector 0x04) for Timer1 / INT0.
- **C-only:** `recipe.cpp.o.pattern` also routes `.cpp`/`.ino` to C.
- **SDCC 4.5.0 bug:** objects in `libsdcc.lib` reference names (`___eeprom_gptr*`)
  that no longer exist — worked around in `toolchain/lib/gptr_shim.S` (redirects to
  `___eeprom8_gptr*`). Built automatically at link time.
- **USB linker scripts:** for the PIC18F2550/4550, `build.lkr` selects a script that
  excludes the USB RAM banks (`toolchain/lkr/18f2550usb_g.lkr`, `18f4550usb_g.lkr`).

## Known limitations

- ❌ No C++ (SDCC); sketches are C (despite the `.ino` extension).
- ❌ No `String`, no `bool` (use `_Bool`/`unsigned char`), no `Serial` object —
  use the `uart1_*` functions.
- ⚠ `analogWrite` only on pin 18 (CCP1); other pins are ignored.
- ⚠ ADC resolution depends on the chip: 12-bit on the K80, 10-bit on the rest.
- ⚠ The PIC16F877A has no LAT registers — writes go to PORT (RMW hazard on PORTA/B).
- ⚠ On the PIC18F25K80, CAN and UART1 share pins RC6/RC7 and cannot be used at once.
- ⚠ Upload uses the bundled **PICprog 1.9.1** (`tools/picprog-upload` →
  `toolchain/picprog/bin/picprog`). The default programmer is **JDM**; choose K8048
  with `PICPROG_HW=k8048`. The port comes from `{serial.port}` (e.g. `/dev/ttyUSB0`).
- ⚠ PIC18F25K80: the PICprog device-table entry was added (`device_id 0x6180`,
  64-byte write buffer) but is **untested on hardware**. PIC18F2550/4550 and
  PIC16F877A are supported natively by PICprog.
- ~`warning 110` messages ("conditional flow changed by optimizer") from gpasm in
  GPIO code do not block the build.
- Clocks: K80 16 MHz (internal), 2550/4550 48 MHz (20 MHz crystal, HS-PLL),
  877A 4 MHz (XT).
